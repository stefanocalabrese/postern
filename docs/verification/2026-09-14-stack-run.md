# 2026-09-14: Task 14 verification against the running stack

## What this is, and what it is not

The plan's Task 14 Step 2 says to drive the server with
`npx @modelcontextprotocol/inspector` through its browser UI and confirm six
things. **This record does not do that.** No browser UI was driven; nothing
below should be read as an Inspector session. Everything marked "verified"
was checked with `curl` against the real running container, the same method
`dev-docs/decisions/0004-base-images.md` used to prove a masked `tools/call` after
Task 13. One item genuinely needs a human at the Inspector UI and is recorded
as an open, unchecked step at the end, not silently dropped.

## Setup

```bash
docker compose up -d --build
sleep 3
docker compose ps   # both api (8080) and backend-stub (8081) Up
```

Both services came up cleanly. `tools/list` requires a bearer token (the
`api` service's `auth=JWTVerifier` rejects every request, `tools/list`
included, with `401` and no body when `Authorization` is absent -- this
project has no genuinely-unauthenticated route once `docker-compose.yml`'s
JWKS/issuer pair is set, which is the deliberate choice `dev-docs/decisions/
0004-base-images.md` recorded). A token is minted per call from the stub's
own throwaway IdP:

```bash
TOKEN=$(curl -sS "http://localhost:8081/mint-token?sub=cust_7f3a")
```

Every request below also carries the mandatory `_meta` envelope
(`io.modelcontextprotocol/protocolVersion`, `io.modelcontextprotocol/
clientCapabilities`) that `services/api`'s request validation requires; a
request without it is rejected with `-32602` before it reaches a tool.

## 1. `tools/list` returns exactly the five tools -- verified over HTTP

```bash
curl -sS -i http://localhost:8080/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2026-07-28' -H 'Mcp-Method: tools/list' -H 'Mcp-Name: tools/list' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}'
```

Result: `HTTP/1.1 200 OK`. `result.tools[].name` is exactly, and only:
`banking_start_session`, `accounts.list`, `accounts.get_balance`,
`transactions.list`, `cards.list`. Confirmed.

## 5. `transactions.list` with `days: 4000` is rejected before reaching the backend -- verified over HTTP

```bash
curl -sS -i http://localhost:8080/mcp \
  -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' \
  -H 'MCP-Protocol-Version: 2026-07-28' -H 'Mcp-Method: tools/call' -H 'Mcp-Name: transactions.list' \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"jsonrpc":"2.0","id":5,"method":"tools/call","params":{"name":"transactions.list","arguments":{"account_ref":"acc_7f3a","days":4000},"_meta":{"io.modelcontextprotocol/protocolVersion":"2026-07-28","io.modelcontextprotocol/clientCapabilities":{}}}}'
```

Result: `HTTP/1.1 200 OK` (FastMCP returns tool errors inside a 200, per
CLAUDE.md's "Version traps"), body:

```json
{"jsonrpc":"2.0","id":5,"result":{"content":[{"text":"1 validation error for call[transactions_list]\ndays\n  Input should be less than or equal to 365 [type=less_than_equal, input_value=4000, input_type=int]\n...","type":"text"}],"isError":true,"resultType":"complete", ...}}
```

`isError` is `true`; the value is rejected by the `Field(ge=1, le=365)`
constraint on the tool's own input schema before the handler runs. Confirmed
against the backend's own access log for the same time window
(`docker compose logs backend-stub`): the only `GET /transactions` line
present is the one from item 4 above (`days=30`); no `days=4000` request was
ever made to `backend-stub`. Confirmed.

## 6. `tools/list` carries `cacheScope: "private"` and `ttlMs` -- verified over HTTP

Taken from the same response as item 1:

```json
"cacheScope":"private", ... "ttlMs":60000
```

`services/api/server.py` passes `cache_scope="private"` and
`cache_ttl=settings.cache_ttl_seconds` to `FastMCP(...)`;
`services/api/settings.py::Settings.cache_ttl_seconds` defaults to `60` and
`docker-compose.yml` does not override `POSTERN_CACHE_TTL_SECONDS`, so `60`
is what is in effect here. `60 * 1000 = 60000`, matching Task 4's
in-process measurement (`tests/test_server_assembly.py::
test_cache_ttl_seconds_and_scope_reach_the_wire`) exactly. **No discrepancy
found**: the unit Task 4 measured in-process (seconds in, milliseconds out,
factor 1000) holds over real HTTP through the built container too. This is
not the "real finding" the plan's Step 2 item 6 warned might turn up --
it is confirmation that the value is stable across environments.

## 7. Header/body mismatch returns HTTP 400 with `-32020` -- re-verified over HTTP

```bash
curl -sS -i http://localhost:8080/mcp \
  -H 'Content-Type: application/json' \
  -H 'Mcp-Method: tools/list' \
  -H 'Mcp-Name: cards.list' \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"cards.list","arguments":{}}}'
```

Result:

```
HTTP/1.1 400 Bad Request
content-type: application/json

{"jsonrpc": "2.0", "id": 1, "error": {"code": -32020, "message": "Header mismatch", "data": "Mcp-Method 'tools/list' does not match body method 'tools/call'"}}
```

Matches Task 13's finding exactly (`Mcp-Method` disagrees with the body's
`method`, rejected before any handler runs, no `Authorization` header
needed to reach this check). Confirmed.

## What was not, and could not be, verified this way

**MCP Inspector was not run.** The above seven items were checked by talking
JSON-RPC over HTTP directly, the same way `dev-docs/decisions/0004-base-images.md`
proved a masked `tools/call` after Task 13. That covers every claim in the
plan's Step 2 that is a statement about response *content* or HTTP *status*.
It does not cover the one claim that is about the *client experience*:
whether a real MCP client, using Inspector's own Streamable HTTP transport
and session handling rather than a hand-built curl request, can connect,
discover the catalog, and drive each tool through a UI without a
client-side error. That is a genuine gap, left open rather than asserted:
